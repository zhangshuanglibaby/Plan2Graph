# 库存低量预警实施计划

> 来源：2026-10-20 由助手虚构的开发场景，不是实际项目中的 Agent 原始计划。仅供本地流程演练，不计入阶段 5.3 的五条真实计划；未取得发送给外部模型的单独许可。

仓库人员现在靠手动筛选库存表寻找缺货商品。此次增加每个商品的预警阈值、后台预警列表和每天一次的汇总提醒。

## 工作安排

1. 确定可售库存的计算口径和阈值的默认值，明确停用商品及库存为零的处理方式。
2. 在商品配置中保存预警阈值，并为旧商品补上默认值。库存读取接口沿用现有库存数据，不另建一套手工维护的库存数。
3. 根据统一的库存口径实现低量商品查询，返回当前可售数、阈值和最近更新时间；查询不能把停用商品列入预警。
4. 管理页面可以先做筛选和列表布局；接入查询接口后展示实际预警商品，并允许有权限的人员修改阈值。
5. 准备每天一次的汇总任务和消息模板。消息模板可以与查询接口并行准备，但定时任务必须复用已经确认的低量商品查询口径，避免列表与提醒数字不一致。
6. 加入每日发送记录，避免任务重试时对同一日期重复发提醒；发送失败应留下可核对的失败状态。
7. 查询、页面和定时提醒完成后，用库存跨越阈值、停用商品、重复触发和消息失败的样本核验列表与提醒内容。
