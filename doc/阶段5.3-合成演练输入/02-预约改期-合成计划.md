# 预约改期功能实施计划

> 来源：2026-10-20 由助手虚构的开发场景，不是实际项目中的 Agent 原始计划。仅供本地流程演练，不计入阶段 5.3 的五条真实计划；未取得发送给外部模型的单独许可。

服务预约目前只能取消后重新下单。此次允许用户在开始前改期一次，同时避免两人占用同一个服务时段。

## 工作安排

1. 确定允许改期的时间窗口、次数限制和可预约时段的计算规则，并与现有取消规则核对冲突。
2. 按上述规则扩展预约记录，保存改期次数和变更前后的时段；历史预约不应因此变成不可读取。
3. 在已有时段查询能力上增加改期可选时段查询。查询可以与页面日历布局并行开发，但接入真实数据之前要完成接口约定。
4. 实现改期提交接口：校验当前预约状态与次数，在一次事务中释放旧时段、占用新时段并记录变更。并发请求只能有一个成功，失败请求不得释放旧时段。
5. 页面在预约详情中展示改期入口、可选时段和提交结果；只有查询接口可用后才能接入真实时段，只有提交接口可用后才能完成改期操作。
6. 准备改期成功与失败的通知文案。通知发送依赖改期事务成功，但文案准备可以与接口开发并行；通知失败不得回滚已经成功的改期。
7. 接口和页面联通后，验证临界时间、重复改期、并发抢占与通知失败，特别检查旧时段和新时段的最终占用状态。
