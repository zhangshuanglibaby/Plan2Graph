# 客户名单导入实施计划

> 来源：2026-10-20 由助手虚构的开发场景，不是实际项目中的 Agent 原始计划。仅供本地流程演练，不计入阶段 5.3 的五条真实计划；未取得发送给外部模型的单独许可。

现有后台只能逐个新增客户。此次要让运营人员上传 CSV，先预览校验结果，再确认导入。首版不处理超过 10,000 行的文件，不覆盖已有客户。

## 工作安排

1. 与运营人员确定 CSV 字段、必填项及重复客户的判定规则，整理一份可用于接口和页面的字段说明。
2. 根据字段说明实现 CSV 解析与逐行校验，返回行号和错误原因；解析失败时不写入客户数据。
3. 基于解析结果提供预检接口，汇总有效行、错误行和重复行，供页面展示。预检不得直接创建客户。
4. 使用同一套校验和重复判定规则实现确认导入接口。对重复提交使用导入批次标识防止重复创建，并记录每行的处理结果。
5. 页面先完成选文件和结果列表的静态布局，这部分可与后端解析并行；接入预检接口后，再实现错误行展示和确认按钮。
6. 确认按钮只有在预检成功后才能调用导入接口。导入结束时展示成功数、跳过数和失败数，不把预检成功误写成导入成功。
7. 等预检、确认导入和页面接入完成后，用含缺失字段、重复客户及重复提交的 CSV 做端到端验证，并核对实际写入数量。
