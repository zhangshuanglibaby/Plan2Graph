# 客服工单附件功能实施计划

> 来源：2026-10-20 由助手虚构的开发场景，不是实际项目中的 Agent 原始计划。仅供本地流程演练，不计入阶段 5.3 的五条真实计划；未取得发送给外部模型的单独许可。

客服目前只能在工单里写文字。此次允许上传少量截图和文档，供有该工单访问权限的人员查看；附件不能通过公开链接直接访问。

## 工作安排

1. 明确允许的文件类型、单文件大小、每单数量和保留期限，并梳理工单查看权限。
2. 设计附件元数据与工单的关联方式，记录原文件名、实际存储标识、上传者和创建时间；元数据不保存文件内容。
3. 实现上传接口，先校验工单权限、数量和文件限制，再写入私有存储并保存元数据。失败时清理已经上传的临时文件，避免孤儿附件。
4. 实现附件列表与下载接口。列表可在元数据结构确定后开发；下载必须先验证当前用户对所属工单的访问权限，再读取文件。
5. 工单页面先完成附件区域布局，这部分可与上传接口并行。接口可用后再接入上传进度、附件列表和受权限保护的下载操作。
6. 增加工单删除后的附件清理流程。清理可以异步进行，但必须记录失败并支持重试，不能在删除工单后留下永久可访问的文件。
7. 等上传、下载、页面和清理流程接通后，验证越权访问、错误文件类型、上传中断、重复删除及清理失败，核对存储和元数据一致性。
