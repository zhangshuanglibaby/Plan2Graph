# Plan2Graph：Python CLI

`server/` 已实现 `plan2graph generate` 的文件与标准输入读取、Mermaid 输出及主要错误诊断。生成时计划文本会发送至 DeepSeek；摘要、待确认关系和被跳过关系的说明写入标准错误。阶段 3 的 M1 技术出口已按有限证据收束：CLI 有离线测试，用户已用真实密钥手动验证文件输入与标准输出、文件输入与 `-o` 文件输出、标准输入与标准输出，并预览了合成示例的输出。独立新用户仅依 README 走通的验收暂缓，尚未记作通过。

## 安装与配置

需要 Python 3.11 或更新版本。在 `server/` 目录运行：

```bash
python3 -m venv .venv
source .venv/bin/activate
python -m pip install -e '.[test]'
```

把 `DEEPSEEK_API_KEY` 设置为环境变量，或写在 `server/.env` 中。不要将密钥提交到仓库。安装依赖可能需要网络；实际生成需要连接 DeepSeek。请只传输允许发送至该服务的计划文本。

可选配置：`DEEPSEEK_MODEL` 默认使用 `deepseek-flash`，这是模型别名，不代表已确认具体服务端版本；`DEEPSEEK_TIMEOUT_SECONDS` 默认 30 秒；`DEEPSEEK_MAX_TOKENS` 默认 4096；`PLAN2GRAPH_MAX_INPUT_CHARS` 默认 20000 字符。输入超过上限会报错，不会截断。

## 生成任务图

没有自己的计划时，可使用已保存的 `server/doc/plan.md`。内容如下，仅作练习输入，与阶段 2.6 的四份评估样例无关：

```markdown
# 帮助中心与工单后台改进计划

## 工作项

1. 为帮助中心增加常见问题搜索，完成搜索结果和空结果的页面测试。
2. 为工单后台增加按标签筛选，完成筛选接口和权限测试。

## 排期建议

建议先完成常见问题搜索，再安排工单标签筛选，便于团队集中评审。两项分别验收；计划没有说明工单标签筛选需要使用常见问题搜索的交付物。
```

以下命令均在 `server/` 目录运行，输入文件使用 UTF-8 编码；生成命令会将计划文本发送至 DeepSeek：

```bash
plan2graph generate doc/plan.md
plan2graph generate doc/plan.md -o doc/plan.mmd
cat doc/plan.md | plan2graph generate - -o doc/plan.mmd
```

不传 `-o` 时，Mermaid 源码写入标准输出，便于重定向或传给其他工具；传入 `-o` 时写入指定的 `.mmd` 文件，标准输出不再包含图。两种模式下，摘要和关系列表均写入标准错误，不会混入 Mermaid 源码。首版不自带渲染器。

要在支持 Mermaid 的 Markdown 预览中查看本次生成的图，请打开 `server/doc/plan.mmd`，复制全部内容；在 `server/doc/` 下新建一个临时 Markdown 文件，把源码放进以 `mermaid` 标记的围栏代码块，再打开该文件的 Markdown 预览。围栏代码块是首尾各一行三个反引号的区域：开头写 `mermaid`，结尾只写三个反引号。若编辑器不支持 Mermaid，请使用自己已有的 Mermaid 渲染环境；不要为了预览把敏感计划上传到公共网站。已有的 [阶段 3 虚线渲染样例](doc/阶段3-CLI渲染验收.md)可用于检查预览功能，但不是 `doc/plan.mmd` 的实时结果。

`-->` 是有原文依据的确定依赖，方向为“前置任务到后续任务”；`-.->` 是待确认的候选关系，不能当成已证实的阻塞条件。CLI 会在标准错误中说明候选关系的原因。若候选关系会使展示图成环，图中不画这条边，并在标准错误中说明跳过原因。任务图的结构校验不能证明依赖在业务上一定正确，仍需人工复核。

上述合成计划只有排期建议，没有说明交付物依赖：生成无连线图或待确认虚线都可能需要人工核对，不应仅凭“先做”画确定依赖实线。模型每次返回的关系和原因措辞可能不同。

## 失败与测试

失败时命令返回非零状态：输入或参数错误为 2，输出文件错误为 3，配置错误为 4，模型请求或响应错误为 5，任务图结构错误为 6。输入输出使用同一路径会被拒绝；写文件时先写临时文件再替换目标，避免失败覆盖已有图。
